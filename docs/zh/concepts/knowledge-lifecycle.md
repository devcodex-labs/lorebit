# 知识生命周期：让资料变化可追踪

<span class="lorebit-label">核心概念 · 知识不是一次写入后永久正确</span>

资料会更新、撤回、拆分或被新版本替代。用户需要的是一套能让答案跟随这些变化的工作流，而不是只把文本永久堆进索引。

## 一个知识单元的状态

| 状态 | 含义 | 用户可见结果 |
|---|---|---|
| 已发现 | 来源已被识别，但尚未允许进入回答 | 不参与检索 |
| 已摄取 | 原文与来源已被记录 | 可等待后续处理 |
| 已索引 | 必需索引已完成 | 可以成为候选证据 |
| 已激活 | 当前版本允许进入回答 | 可被检索并返回引用 |
| 已替代 | 新版本接管同一事实 | 旧版本不再作为默认答案依据 |
| 已归档 | 保留审计或回溯需要 | 不进入普通检索 |

## 更新不是简单覆盖

更新一份政策页时，需要分别回答：原文是否变了、哪些知识单元受影响、哪些索引需要重建、旧引用是否还能解释当时的答案。这个过程需要 revision、idempotency 和激活状态，而不是一次无痕覆盖。

## 失败时保持事实边界

如果某个 adapter 没有完成重建，系统不应假装所有检索结果已经最新。正确行为是保留清晰状态、支持重试，并让调用方知道当前保证到哪里为止。
