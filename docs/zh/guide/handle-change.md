# 处理资料更新、替代与撤回

<span class="lorebit-label">让知识持续可靠 · 更新不是无痕覆盖</span>

资料变化是知识流程的正常输入，而不是异常。政策修改、帮助页重写、地区范围变化和原文撤回都会改变哪些回答还能被相信。lorebit 的目标不是让旧文本永远留在索引中，而是让使用者知道变化影响什么、正在处理到哪里、目前还能保证什么。

## 先辨认发生了哪种变化

| 变化 | 需要判断的关系 | 对当前回答的影响 |
|---|---|---|
| 修订 | 新内容是补充还是替代同一事实？ | 可能需要重新检查引用旧版的结论。 |
| 拆分或合并 | 原有资料被分成多份，还是多份合为一份？ | 不能假设旧引用仍能完整表达新规则。 |
| 撤回 | 原文是否不再可信，是否有替代主证据？ | 旧证据停止作为默认依据；没有替代时要暴露未知。 |
| 适用范围变化 | 地区、套餐、日期或权限边界是否改变？ | 需要避免把旧范围泛化到新问题。 |
| 处理失败 | 哪一步尚未完成、能否安全重试？ | 不能宣称所有结果都已经是最新。 |

## 用五步处理变化

1. **发现并记录**：明确变的是哪份来源、哪个修订、由谁确认。
2. **分类关系**：判断补充、替代、并行、撤回或范围变化，避免只看发布时间。
3. **评估影响**：哪些知识空间、答案、证据或处理能力受到影响。
4. **处理并验证**：让新资料完成必要的审阅、处理和激活；记录仍未完成的部分。
5. **向使用者说明保证**：说明什么已更新、什么待处理、何时要重新回答或转人工。

这五步的重点是可见性。即使未来实现采用异步重建、队列或不同的存储策略，使用者也必须能理解当前的事实边界。

## 例子：退款政策被替代

假设政策负责人发布了新版本，并声明旧版从明天起不再适用。正确流程不是只把新 PDF 上传进去：

- 标出新旧修订的替代关系和生效时间。
- 找出引用旧版退款条件的知识单元与答案路径。
- 让新版本完成审阅与必要处理，直到它能承担默认证据角色。
- 在过渡期明确显示哪些地区、套餐或问题还未确认。
- 旧版保留用于解释历史结果，但不再作为新问题的默认主依据。

## 当前可做与目标版本的区别

| 阶段 | 当前文档阶段 | 0.x 目标行为 |
|---|---|---|
| 记录变化 | 在资料台账和负责人流程中写下关系与影响。 | lorebit 让使用者查看修订关系、影响范围和处理状态。 |
| 执行更新 | 由团队协调重建与验证。 | lorebit 协调所需能力的处理状态与安全重试语义。 |
| 对外说明 | 由业务人员手动标注回答限制。 | lorebit 将当前保证、未完成状态与旧证据边界传递到结果中。 |

## 常见失败

| 失败 | 风险 | 修正方式 |
|---|---|---|
| 直接覆盖旧资料 | 无法解释历史回答为何如此，也无法知道谁受影响。 | 保留修订关系，区分替代与补充。 |
| 新资料一出现就默认激活 | 未审阅、不适用或处理未完成的内容可能进入回答。 | 等待准入与处理状态满足合同。 |
| 只重建索引，不检查引用 | 结果看起来新，实际仍引用旧证据。 | 把受影响的回答与证据链纳入影响评估。 |
| 把“处理中”显示为“已更新” | 使用者做出超过当前保证的决策。 | 显示完成范围、剩余工作与降级建议。 |
