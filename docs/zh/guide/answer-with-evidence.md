# 交付带证据的回答

<span class="lorebit-label">建立第一条流程 · 结果不是一段文字，而是一份可追溯的判断</span>

用户最终要的不是“检索命中了几段文本”，而是一个能采取行动、知道边界、能回到资料核对的回答。lorebit 的 0.x 目标合同要求把回答与其证据一起组织，而不是把 citation 留给调用方临时拼接。

## 一个可使用的回答应包含什么

| 组成 | 使用者为什么需要它 | 退款规则示例 |
|---|---|---|
| 结论 | 知道现在可以采取什么行动 | 标准套餐在满足购买时间条件时可申请退款。 |
| 适用范围 | 知道结论是否适用于当前问题 | 仅适用于中国大陆、标准套餐和当前政策日期。 |
| 证据片段 | 能核对具体依据 | 退款政策第 3 节的相关条款。 |
| 来源与版本 | 能确认资料是否仍是当前依据 | 《退款政策》2026-xx-xx 修订版。 |
| 状态与限制 | 知道是否存在更新、冲突或能力边界 | 该条款已激活；无地区信息时需补充后再判断。 |

证据不是装饰性的链接。它必须能支撑关键结论，并足以让人判断资料为何适用。

## 从问题到回答的六个判断

1. **识别范围**：问题属于哪个知识空间，是否缺少地区、套餐或时间等必要信息。
2. **选择候选资料**：只从允许、激活且范围适用的资料中寻找证据。
3. **检查修订关系**：确认没有被新版本替代、撤回或标为待处理。
4. **组织证据包**：保留足够的片段、来源、版本和适用条件，避免只拿一句相似文本。
5. **形成结论**：结论不能超出证据能支持的范围。
6. **表达限制**：证据不足、状态未完成或能力不支持时，说明未知什么以及下一步。

这六步是用户可见行为，不要求今天存在某个特定 pipeline、模型、重排器或方法名。实现可以演进，但结果语义不能被静默改变。

## 没有合格证据时，正确的结果是什么

| 情况 | 不能做什么 | 应交付什么 |
|---|---|---|
| 找到相似文本但无法确认适用范围 | 把它写成确定答案 | 说明需要补充范围，或只给出带限制的背景。 |
| 资料正在替代或重建 | 假设最新版本已经可用 | 显示更新状态，说明当前保证与等待动作。 |
| 引用位置丢失 | 返回无来源的流畅文本 | 缩小结论、要求补证据或转人工。 |
| adapter 缺少必要能力 | 静默采用不同策略并冒充相同保证 | 说明缺少什么能力以及对结果的影响。 |

“我不知道”不是系统失败；在证据合同下，它是比无依据断言更可信的结果。

## 当前可做与目标版本的区别

| 阶段 | 当前文档阶段 | 0.x 目标行为 |
|---|---|---|
| 设计回答 | 用问题卡和资料卡桌面演练每个结论需要什么证据。 | lorebit 组织可追溯的回答结果与证据包。 |
| 说明边界 | 由团队在评审中检查限制是否说清。 | lorebit 暴露适用范围、版本、状态和缺口，而非只返回文本。 |
| 验收 | 人工对照资料检查答案。 | 实现必须通过本页和“带证据回答”场景的端到端验收。 |
