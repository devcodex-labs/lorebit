# 诊断质量与恢复

<span class="lorebit-label">让知识持续可靠 · 没有合格证据时也要说清事实</span>

可靠性不是只在一切顺利时才有意义。真正的工作流要能识别资料过期、引用缺失、能力不足和重建未完成，并把下一步交给能处理的人。

## 每次评审先检查四件事

| 检查项 | 通过的信号 | 未通过时先做什么 |
|---|---|---|
| 来源 | 回答只使用已批准、有人负责的资料 | 移除不明来源，补充主证据。 |
| 版本 | 能说明采用的是哪个版本及适用范围 | 标为待确认，不把旧版当成默认依据。 |
| 引用 | 能回到原文和支撑答案的片段 | 缩小回答范围或拒绝做无证据断言。 |
| 状态 | 知道相关索引、重建或替代是否完成 | 明确“正在更新”，不要暗示结果完全最新。 |

## 质量是五类可解释信号，不是一条神秘分数

未来实现可以计算分数或使用评测，但使用者不能只看到一个没有含义的“质量 0.87”。0.x 目标合同至少要让他们判断五类信号：

| 信号 | 它回答什么问题 | 典型恢复方向 |
|---|---|---|
| 范围 | 这个问题是否落在知识空间内？ | 补充地区、套餐、时间或转到正确流程。 |
| 来源 | 资料是否被允许、有人负责？ | 补齐责任信息或排除不明资料。 |
| 修订 | 当前证据是否仍然有效？ | 检查替代、撤回和处理进度。 |
| 引用 | 关键结论能否回到具体位置？ | 缩小结论、补定位或转人工。 |
| 能力 | 当前 adapter 是否能兑现本次需要的保证？ | 声明缺口，调整流程或补充能力。 |

## 四种常见失败及恢复方向

| 你看到的现象 | 常见原因 | 恢复方向 |
|---|---|---|
| 回答有内容但没有可靠出处 | 资料没有可引用位置，或检索只返回了相似片段 | 回到资料与证据卡，补来源、版本和原文位置。 |
| 新规则上线后答案仍像旧规则 | 替代关系或重建状态没有被确认 | 用生命周期表定位受影响的资料与未完成步骤。 |
| 某类问题总是答得模糊 | 当前 adapter 缺少关键词、过滤、关系或版本能力 | 先声明能力缺口，再决定调整问题、补适配器或暂不支持。 |
| 团队无法判断是否可以继续使用结果 | 状态只在内部可见，缺少面向使用者的边界 | 把“已更新到哪里”和“尚未保证什么”写进工作流卡。 |

## 先恢复事实，再追求覆盖率

当关键资料没有通过检查时，宁可让回答缩小范围、要求补充资料或转人工，也不要用未经确认的内容填满答案。覆盖更多问题是后续优化；能清楚说明“知道什么、依据是什么、还不知道什么”才是第一优先级。

## 把恢复设计成用户看得懂的路径

| 发生的事 | 使用者首先应看见 | 可继续的动作 |
|---|---|---|
| 引用缺失 | 哪项结论不能被证据支撑 | 补资料、缩小结论或转人工。 |
| 新资料处理中 | 哪个范围已经更新、哪个范围仍待处理 | 等待处理、避免依赖未完成范围。 |
| 资料撤回 | 哪些结论不再能作为默认依据 | 选择替代资料或暂停回答。 |
| 能力不足 | 缺少哪种能力、会影响什么保证 | 调整问题边界、选用补充 adapter 或暂不支持。 |

当前阶段可以用工作流卡和资料评审记录这些判断；0.x 目标版本必须把它们投影为结果中的状态、限制和恢复方向。内部异常、重试次数或 provider 日志不能替代这份用户可见说明。
