# 接入与审阅资料

<span class="lorebit-label">建立第一条流程 · 先确认什么资料能支撑回答</span>

一条知识工作流的可靠性，取决于它允许使用什么资料、资料在何种状态下可以参与回答，以及能否在回答之后回到那份资料。开始时不必收集所有文件；先准备一小组能覆盖真实问题、有人负责且能识别版本的来源。

## 1. 圈定允许进入回答的资料

以“根据最新产品规则回答客户问题”为例，先把来源分成三类：

| 类别 | 例子 | 处理方式 |
|---|---|---|
| 主证据 | 已审核的产品规则、政策页、版本化帮助文档 | 可以支撑面向用户的回答。 |
| 辅助说明 | FAQ、培训材料、公告摘要 | 只能补充背景，不能覆盖主证据。 |
| 不可引用资料 | 私人笔记、过期截图、没有负责人的转述 | 不进入答案依据。 |

如果一份资料没有明确来源或负责人，它也不能在“资料很多”时自动变得可信。

## 2. 为每份来源留下最小证据卡

在现有的资料台账、知识库或项目文档中记录下列信息即可；它不是当前 lorebit 的 API 或配置格式。

| 需要记录 | 为什么重要 |
|---|---|
| 来源位置与负责人 | 出现争议时能找到原文和确认人。 |
| 当前版本或发布日期 | 能判断答案基于哪一版规则。 |
| 适用范围 | 防止把地区、套餐或旧版本规则用错。 |
| 替代与撤回信号 | 知道何时停止把它当作默认证据。 |
| 可引用位置 | 至少能回到页面、章节或原文片段。 |

## 把资料卡变成准入决定

资料卡不是“收集信息”的表格，而是决定一份资料能否作为默认依据。审阅时需要留下一个清楚结论：

| 结论 | 什么时候使用 | 用户可见含义 |
|---|---|---|
| 可以作为主证据 | 来源、负责人、修订、范围与定位都充分 | 未来目标版本可让它参与符合范围的默认回答。 |
| 只能补充背景 | 能解释上下文，但无法独立支持关键结论 | 不应覆盖主证据或生成确定性结论。 |
| 待补资料 | 缺负责人、范围、版本或可引用位置 | 不能静默进入回答路径。 |
| 不可引用 | 已撤回、过期、私人转述或无从核对 | 只允许保留为人工背景，不参与默认依据。 |

这份决定应与资料本身的处理状态分开：一份准入资料在处理未完成时仍然不能承担“当前可回答”的保证。

## 3. 用一个问题检查资料是否够用

选择一个真实客户问题，逐份检查：这份资料是否直接回答了问题？是否仍在适用期？回答时能否指出具体位置？如果三个问题中任一项答不上来，就把它标为“待补证据”，而不是让检索策略猜测。

## 4. 把变化交给生命周期处理

资料准备完成不代表永久有效。来源被替换、撤回或拆分时，要把证据卡交给生命周期流程，明确哪些答案需要重新检查。

## 当前可做与目标版本的区别

| 阶段 | 当前文档阶段 | 0.x 目标行为 |
|---|---|---|
| 准备来源 | 在现有台账和评审流程中维护资料卡。 | lorebit 保留来源、修订、范围、负责人和准入结论。 |
| 审阅状态 | 人工确认哪些资料可用。 | lorebit 让使用者区分待审阅、处理中、已激活、已替代和已撤回。 |
| 回答引用 | 通过桌面演练检查原文位置。 | lorebit 让证据和引用可回到来源与具体修订。 |
